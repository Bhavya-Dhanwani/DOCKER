Docker, rewritten in Rust.
Light on RAM and disk.

The command is still docker, so your Dockerfiles, compose files and scripts keep working. No always-running daemon, a small static program, and a desktop app that shows live RAM, disk and CPU for every container.

Download

One line installs the right file for your machine, or pick a file yourself.

One-line install

Windows (PowerShell):

irm https://raw.githubusercontent.com/Bhavya-Dhanwani/DOCKER/main/install.ps1 | iex

Linux and macOS:

curl -fsSL https://raw.githubusercontent.com/Bhavya-Dhanwani/DOCKER/main/install.sh | sh

SystemDownloadNotes
Windows tested Intel / AMD (x64) ARM64 Installer, no admin needed. It asks where to put the program and where to keep images and the Linux VM disk. Needs WSL2 for Linux containers.
Linux new x86_64 ARM64 Unpack, then sudo ./install.sh. Runs containers natively; also works without root (docker --rootless).
macOS new Apple silicon Intel Linux containers run in a small VM: brew install lima, then docker vm init.

The Windows version is the most tested. The Linux and macOS packages are new: if something does not work, please open an issue.

What you get

Everyday Docker, with fewer resources.

Same commands

run, build, compose, exec, ps --format, inspect, logs, events, push/pull and more. Dockerfiles, multi-stage builds and compose files (overrides, profiles, secrets) work as they are.

Low RAM and disk

No daemon running all day. Layers are stored once and shared. Container writes live in RAM, so nothing is written to your SSD unless you mount a volume.

A real desktop app

Containers, images, volumes and networks. Live RAM, disk and CPU bars with history, run several images together as a group, an image catalog, and logs, stats and shell shortcuts.

Works with your tools

Speaks the Docker Engine API, so the real Docker CLI and the Docker SDK for Python can talk to it (docker daemon).

Any image

docker run <image> pulls what is missing. Intel-only images run on ARM machines through built-in emulation (slower than native).

Rootless and swarm

Run without root on Linux, build rootless, and use a single-node swarm with services, stacks, secrets and configs.

Questions

Does it replace Docker Desktop?

For running and building Linux containers, yes. On Windows it uses a small hidden WSL2 distribution, on macOS a Lima VM, on Linux no VM at all.

Does it run Windows, macOS or Android containers?

No, and Docker does not either: containers share the host's Linux kernel.

What is not supported?

Swarm across several machines, log timestamps (logs -t), compose watch, and a few exotic run options (--gpus, --device, --ipc). diff, commit and export need a running container. See the roadmap for the full list.

Where is my data stored?

On Windows the installer asks. Images and the VM disk can grow to many gigabytes, so pick a drive with space. Uninstalling keeps the data folder.

How do I remove it?

Windows: Settings, Apps, Sasta Docker. Linux and macOS: curl -fsSL https://raw.githubusercontent.com/Bhavya-Dhanwani/DOCKER/main/install.sh | sh -s -- --uninstall
